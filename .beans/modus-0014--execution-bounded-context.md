# The execution bounded context

Why: triggers and agent runs are the product's verb. Three `Enforcement gap:` lines in
`doc:00-constitution` — questions asked per work item, peak context per run, and the 240k
at-risk flag of `doc:00-constitution#context-budget` — name this context as the recorder
and cannot close until it exists.

Success criteria:

- `Trigger` and `AgentRun`. `AgentRunStarted`, `AgentRunOutput`, `AgentRunCompleted`,
  `ContextBudgetExceeded` published; `WorkItemTransitioned` consumed.
- Context-budget accounting is domain state, so the ceiling is evaluated in the model, not
  in a transport or a script. Token counts are a value object, never a raw `Long`.
- **The published usage shape is per-request and cache-aware.** This is the expensive part
  to get wrong — see below — so it is a criterion, not an implementation detail.
- The run output stream is a port here and an adapter in `bean:0021`.

Sequencing with `bean:0015` (`doc:10-architecture#bounded-contexts` §3.1's mutual
published-language cycle): this bean lands first, so its `MemoryRecorded` consumption is
deferred — `bean:0015` does not exist yet and there is no type to import. That criterion is
`bean:0015`'s to satisfy, wiring the subscriber into this context once `MemoryRecorded`
exists, not duplicated here. `bean:0015` is not a blocking edge on *this* bean: this bean
has nothing of `memory`'s to consume before that point. Blocks `bean:0016`, `bean:0020`.

## The usage vocabulary this context publishes

Stated here because a published language is expensive to change
(`doc:10-architecture#bounded-contexts` §3.1: an ADR plus a migration), and because silence
here is what let a wrong model reach
`bean:0020` and `backoffice/src/agent/transport.ts` unchallenged (`bean:0069`).

Every clause below is a measured property of a Claude Code transcript. The evidence is
`domains/modus/cost/replay/baseline.md`, generated by `tools/cost_lib.py` and re-checkable
with `python3 tools/cost-replay.py --check`; `bean:0069` records the measurement. No figure
is repeated here, because a corpus number in a merged document is stale by the next session
(`bean:0059`).

1. **Usage is per-request, never a running cumulative total.** `AgentRunOutput` carries one
   request's usage. `output_tokens` is observed *falling* between consecutive messages,
   which a cumulative counter cannot do.
2. **A message is reported in more than one frame, and frames are deduplicated on
   `message.id`.** The authoritative frame is the one with the largest `outputTokens`; a
   partial frame carries a mid-stream count a later frame supersedes. Summing frames
   multiplies the bill; keeping the first loses close to half the output. The other four
   kinds are byte-identical across frames, and the replay asserts that on every run — if it
   ever fails, this rule is wrong and the frames are independent charges.
3. **Five token kinds, `tools/cost_lib.py`'s `USAGE_KINDS` verbatim** — `inputTokens`,
   `outputTokens`, `cacheReadTokens`, `cacheWrite5mTokens`, `cacheWrite1hTokens`. The 5m and
   1h cache writes stay split because they are billed at different multipliers. Cache reads
   dominate the corpus; a two-field counter prices a fraction of a percent of real spend.
   Two names for one concept across the Kotlin, Python and TypeScript halves is a defect.
4. **`ContextBudgetExceeded` is evaluated on peak context**, defined as
   `max(inputTokens + cacheReadTokens + cacheWrite5mTokens + cacheWrite1hTokens)` over the
   run's requests — `cost_lib.peak_context_tokens`. It is derivable only because of (1) and
   (3): a cumulative `tokensIn`/`tokensOut` pair has no single request to take a maximum of.
5. **`AgentRunCompleted` for a cancelled run is synthesised by this context, not received.**
   No line of a stored transcript and no field of a subagent's `*.meta.json` sidecar carries
   an exit code, a status or an end reason, and a cancelled run's process is killed before
   it could write one. A consumer that waits for a terminal frame hangs forever. Being the
   synthesiser is this context's job, and the reason it is stated here rather than assumed.
6. **Money is `Usd`, integer micros** (`doc:20-ddd-practices#value-objects` §3). Cost is
   derived from usage and the price book, never carried as a float and never estimated into
   a spend record (`doc:60-cost-model#spend-record`).
