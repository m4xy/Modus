# The execution bounded context

Why: triggers and agent runs are the product's verb. Three `Enforcement gap:` lines in
`doc:00-constitution` — questions asked per work item, peak context per run, and the 240k
at-risk flag of `doc:00-constitution#context-budget` — name this context as the recorder
and cannot close until it exists.

Success criteria:

- `Trigger` and `AgentRun`. `AgentRunStarted`, `AgentRunOutput`, `AgentRunCompleted`,
  `ContextBudgetExceeded` published; `WorkItemTransitioned` consumed.
- Context-budget accounting is domain state, so the ceiling is evaluated in the model, not
  in a transport or a script. Token counts are a value object, never a raw `Long`.
- **The published usage shape is per-request and cache-aware.** This is the expensive part
  to get wrong — see below — so it is a criterion, not an implementation detail.
- The run output stream is a port here and an adapter in `bean:0021`.

Sequencing with `bean:0015` (`doc:10-architecture#bounded-contexts` §3.1's mutual
published-language cycle): this bean lands first, so its `MemoryRecorded` consumption is
deferred — `bean:0015` does not exist yet and there is no type to import. That criterion is
`bean:0015`'s to satisfy, wiring the subscriber into this context once `MemoryRecorded`
exists, not duplicated here. `bean:0015` is not a blocking edge on *this* bean: this bean
has nothing of `memory`'s to consume before that point. Blocks `bean:0016`, `bean:0020`.

## The usage vocabulary this context publishes

Stated here because a published language is expensive to change —
`doc:10-architecture#bounded-contexts` says a change to a published contract **needs an
ADR** (`doc:20-ddd-practices` §4.1.5) — and because silence here is what let a wrong model
reach `bean:0020` and `backoffice/src/agent/transport.ts` unchallenged (`bean:0069`).

Every clause below is a measured property of a Claude Code transcript. The evidence is
`domains/modus/cost/replay/baseline.md`, generated by `tools/cost_lib.py`; `bean:0069`
records the measurement and the commands. No figure is repeated here, because a corpus
number in a merged document is stale by the next session (`bean:0059`).

`python3 tools/cost-replay.py --check` re-checks that baseline, but read what it checks
before citing it: it hashes the inputs the baseline recorded and reports **drift** if any
has changed — which any live session causes by appending a line — so a red `--check` says
"the committed figures describe a different input set", not "the figures were wrong". In a
worktree it also needs `--transcripts DIR`, because the project directory is derived from
the checkout path.

1. **Usage is per-request, never a running cumulative total.** `AgentRunOutput` carries one
   request's usage. `output_tokens` is observed *falling* between consecutive messages,
   which a cumulative counter cannot do.
2. **A message is reported in more than one frame, and frames are deduplicated on
   `message.id`.** The authoritative frame is the one with the largest `outputTokens`; a
   partial frame carries a mid-stream count a later frame supersedes. Summing frames
   multiplies the bill; keeping the first loses close to half the output.

   This rests on a premise: the other four kinds are byte-identical across frames of one
   message. If that is ever false the frames are independent charges, discarding the loser
   **undercounts the bill**, and this rule is wrong rather than unlucky.

   **State of that premise, precisely, because the reassuring version is worth nothing.**
   It is *observed to hold* on every run of the replayed corpus, and it is **not
   asserted**. The Python replay renders a disagreement count into a table row: no `raise`,
   no non-zero exit, and its `--check` compares file text after returning early on input
   drift, so a regenerated baseline reading `7 disagreement(s)` would pass. `cost_lib`'s own
   module docstring records that `./gradlew qualityCheck` runs no Python at all. On the
   TypeScript half `framesDisagree` in `backoffice/src/agent/transport.ts` now checks it per
   frame and the console shows a visible notice instead of discarding in silence, and
   `?fault=usage-disagreement` exists so that detector has been **observed firing**
   (`doc:00-constitution#observed-failing`). That is a **detector, not a gate**: it covers
   the TypeScript consumer only, it reports rather than fails, and the Python half — which
   is what produces the committed baseline — remains unasserted. An implementation of this
   context must not treat the premise as guaranteed by tooling. It is guaranteed by nothing.
3. **Five token kinds, `tools/cost_lib.py`'s `USAGE_KINDS` verbatim** — `inputTokens`,
   `outputTokens`, `cacheReadTokens`, `cacheWrite5mTokens`, `cacheWrite1hTokens`. The 5m and
   1h cache writes stay split because they are billed at different multipliers. Cache reads
   dominate the corpus; a two-field counter prices a fraction of a percent of real spend.
   Two names for one concept across the Kotlin, Python and TypeScript halves is a defect —
   including `costUsd`, which is **integer micros** in `doc:60-cost-model#spend-record` and
   in every stored record, and must not acquire a `costUsdMicros` variant to say so.
   An unpriced model id is an error, never a default: `cost_lib.normalise_model` raises on
   one, and a silent fallback prices a run wrongly with nothing on screen to say so.
4. **`ContextBudgetExceeded` is evaluated on peak context**, defined as
   `max(inputTokens + cacheReadTokens + cacheWrite5mTokens + cacheWrite1hTokens)` over the
   run's requests — `cost_lib.peak_context_tokens`. It is derivable only because of (1) and
   (3): a cumulative `tokensIn`/`tokensOut` pair has no single request to take a maximum of.
5. **A per-message status exists; a RUN terminal does not. `AgentRunCompleted` is
   synthesised by this context, not received.**

   Stated in that order because the obvious reading of the shorter claim is false and
   checkably so. Every stored assistant message **does** carry a `stop_reason`
   (`tool_use`, `end_turn`, `stop_sequence`), and error lines carry `apiErrorStatus` and
   `error` — so an implementer looking at the wire *will* find a status field, and a
   specification saying "there is no status" would be contradicted in five minutes. What
   does not exist is a **run** terminal:

   - No field of a subagent's `*.meta.json` sidecar carries an exit code, a status or an
     end reason. This half is absolute.
   - The per-message `stop_reason` does not stand in for one: on most runs the last
     assistant line's `stop_reason` is **null**, and `end_turn` appears on only a small
     minority. `bean:0069` carries the counts.
   - A cancelled run's process is killed before it could write anything at all.

   So a consumer that finds `stop_reason` and settles on `end_turn` hangs on most runs —
   which is precisely the failure this clause exists to prevent, and precisely the mistake
   the shorter false claim would have caused. Being the synthesiser is this context's job.
6. **Money is `Usd`, integer micros** (`doc:20-ddd-practices#value-objects` §3). Cost is
   derived from usage and the price book, never carried as a float and never estimated into
   a spend record (`doc:60-cost-model#spend-record`).
